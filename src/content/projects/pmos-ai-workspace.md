# PMOS (Product Manager Operating System)

> **产品宣言**：“AI 追问 + PRD + 出原型”已经不再是充分差异化。PMOS 的核心使命是：**把需求讨论中的证据、确认、决策、假设与变更，持续绑定到 PRD、可操作原型与验收结果，明确指出哪里尚未一致。**

---

## 🎯 1. 行业痛点与产品定位

在大模型普及的今天，产品经理使用 AI 生成文档面临三大断层：
1. **确定性断层**：AI 生成的 PRD 看似完整，但缺乏“用户真实证据 vs AI 假设推论”的分层标注；
2. **变更断层**：修改某一个字段或需求点时，传统 AI 工具会重写整份文档，导致其他已确认条款被静默篡改；
3. **交付断层**：文档、可操作原型（HTML Prototype）与技术验收标准（AC）割裂，缺乏双向基线同步。

### 竞品对标与战略卡位 (Competitive Matrix)

| 竞品 | 优势能力 | PMOS 的差异化破局点 |
| :--- | :--- | :--- |
| **ChatPRD** | 粗想法提炼 PRD、对话辅导与多页原型 | **超越单一文档输出**：引入 `@生成物` 定向修改与版本基线一致性核验（Consistency Baseline）。 |
| **Aha!** | 补全意见背景、需求追踪与上线清单 | **降低提问冗余**：减少低价值追问，主动提供带理由与替代项的决策建议卡。 |
| **Linear / Jira** | 研发任务编排与 Issue 追踪 | **上游交付枢纽**：PMOS 专注在上游输出带有验收 ID 的高保真交付包，与下游研发系统无缝交接。 |

## 🏗️ 2. 四层核心架构与工作流设计

```
PMOS 四层推进工作流
┌────────────────────────────────────────────────────────┐
│ 1. 需求探索 (Dialogue & Evidence)                      │
│    • 证据分层：[原始证据] [AI推断] [用户确认] [待验证假设] │
├────────────────────────────────────────────────────────┤
│ 2. 结构化方案 (Structured PRD & Spec)                  │
│    • 稳定章节 ID，支持 `@prd` 局部定向修改与精准增量更新 │
├────────────────────────────────────────────────────────┤
│ 3. 敏捷验证 (Interactive HTML Prototype)               │
│    • 真实可操作原型、风格小样、错误态/加载态全链路覆盖 │
├────────────────────────────────────────────────────────┤
│ 4. 交付与一致性基线 (Impact Analysis & Baseline)        │
│    • PRD 或原型变更后，自动分析受影响模块并提示同步授权  │
└────────────────────────────────────────────────────────┘
```

## 🤖 3. 人机共创协作模型 (Human-AI Co-Creation)

- **人类产品经理 (45%)**：
  - 定义业务战略底线与用户真实画像；
  - 评审 AI 提出的方案分支与替代决策；
  - 授权跨生成物的影响面同步（Selective vs Full Sync）。
- **AI 智能协作体 (55%)**：
  - 自动从非结构化访谈中萃取核心需求卡；
  - 遵循一致性规则渲染可交互 Vue 原型；
  - 追踪三类版本状态：系统版本 `V0.2`、项目基线 `vX.Y`、成果修订 `rN`。

---

## 💡 4. 产品复盘与演进规划

当前 PMOS 已完成 V0.2 本地工作台原型验证，支持四层工作流推进与双项目联动演练。后续将进一步探索将本地需求扫描与轻量大模型驱动的敏捷评审相结合，真正成为 AI 时代产品经理不可或缺的超级副驾驶。
